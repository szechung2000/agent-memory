## Note-generation rules

1. Create drafts in an inbox or staging folder.
2. Use a deterministic filename derived from `source_id`.
3. Never overwrite a note with `review_status: approved`.
4. Preserve page, section, table, and figure locators for factual claims.
5. Label paraphrases, inferences, and model-generated applications explicitly.
6. Do not promote claims into the `brain` namespace until their review status
   is `verified` or the user explicitly accepts them as hypotheses.
7. Make retries idempotent: update the same draft rather than appending
   duplicate sections.
8. Re-read and validate the note after writing it.
